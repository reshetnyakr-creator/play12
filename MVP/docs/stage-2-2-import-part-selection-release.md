# Stage 2.2 — Выбор партий MusicXML и Round Navigator

База Stage 2.1 и точка отката `rollback-before-stage-2-2` — `f0d7ed834af564b17cf975426f54494a6f43c38f`. Рабочая ветка `feature/stage-2-2-import-part-selection`.

## Импорт

XML из файла, MXL или вставленного текста проходит одну проверку структуры score-partwise. Классификация учитывает название партии, названия и звуковые идентификаторы инструментов и программы MIDI. Число станов, тактов и нот фиксируется отдельно. При одной распознанной клавишной партии применяется автоматический выбор. При нескольких или отсутствии распознанной клавишной партии открывается выбор по исходным ID с явным режимом объединения. Отмена сбрасывает текущую загрузку. Смена языка сохраняет уже подтверждённый выбор.

В документе сохраняются исходный XML целиком, его контрольная сумма и выбранные ID. Дедупликация учитывает выбранный набор, сохраняя совместимость с ранними импортами полного файла. Преобразователь передаёт только выбранные партии с прежними ID событий, распределением рук и параметрами нот. Темп считывается из первой партии с темповыми указаниями, даже если музыкальные события этой партии исключены. Педализация берётся из выбранных партий. Условие ручного выбора инструмента не расширяет форматы и нотные обозначения, поддерживаемые преобразователем.

## Die With A Smile

В исходном архиве две партии с названием Piano. У P1 указан `keyboard.piano`, у P2 — `keyboard.piano.grand`. У обеих программа MIDI 1, два стана, 219 тактов и 1 594 ноты. Использован переданный MXL с SHA-256 `ee578738e05de419e917258e29bef703103413df8d22bd18044c6815e990c1a8`. Архив в репозиторий не включён.

| Выбор | Всего | Назначено | Пропущено | Время Worker, мс |
| --- | ---: | ---: | ---: | ---: |
| P1 | 1 594 | 1 594 | 0 | 1 152 |
| P2 | 1 594 | 1 594 | 0 | 1 195 |
| P1 и P2 | 3 188 | 0 | 3 188 | 96 |

Каждый результат получен независимой загрузкой MXL через браузер и штатный Worker. Все три варианта сохранили начальный темп 158 BPM и четыре изменения карты, включая начальный темп. Валидатор зафиксировал 0 ошибок назначений. В объединённом варианте это число относится к пустому набору назначений.

На Stage 2.1 прежний путь импорта передал обе партии в двухручную модель и воспроизвёл 0 из 3 188 с теми же кодами. Например, `P1.m0.e3` и `P2.m0.e3` требуют одну физическую клавишу MIDI 57 левой рукой на интервале [0, 1) четверти. Ещё два совпадения в первом такте приходятся на MIDI 61 и MIDI 64 в следующих четвертях. Движок сохранил контакты разных партий раздельно. На одновременной атаке или удержании одной клавиши возникла неопределённость владения. В объединённом импорте 3 110 нот получили `MODEL_CONFLICT_UNRESOLVED_KEY`, ещё 78 — `RECOVERY_PENDING_RELEASE`. Поиск вернул `partial` и сгенерировал 0 кандидатов. Worker завершился штатно в пределах лимита.

При нулевом результате интерфейс показывает причину. Сохранение такой версии требует повторного нажатия «Сохранить в мои мелодии». Правила аппликатуры и модель контактов прежние.

## Round Navigator и регрессии

- Вверх — следующий, вниз — предыдущий. Нижняя стрелка отключена на первом раунде, верхняя на последнем. Геометрия, ручной ввод, перетаскивание, транспорт и Loop Board используют существующую реализацию.
- JavaScript 330/330 и Python 9/9. Расчёты Interstellar Suite 5 249/5 249, Creep 1 468/1 468, Clocks 195/195, He's a Pirate 436/436. В этих четырёх расчётах 0 конфликтов валидатора.
- Chromium проверил однопартийный MusicXML, автоматический выбор клавишной из смешанного файла, отсутствие автоклассификации по двум станам, ручной выбор, отмену кнопкой и Escape, три сохранения одного MXL, сохранение после смены языка, карту темпа из непереданной партии. В Main проверены стрелки, их границы, ручной ввод и перетаскивание при 1440×900, 820×1180 и 375×667. Проверены названия стрелок в RU/EN Main и Tutorial.
- Физические iPad и iPhone не использовались.

Браузерный тест `MVP/tests/browser/import-part-selection.cjs` запускается из корня репозитория с запущенным статическим HTTP-предпросмотром и Playwright. `PLAY12_TEST_BASE_URL` задаёт URL предпросмотра, `PLAY12_TEST_SMILE_MXL` — путь к контрольному архиву. Без контрольного архива выполняются проверки на синтетических MusicXML и штатной фортепианной фикстуре.
