Проверки выполнялись с `b76b907ac53ee7742b546cb964c0443aea9f845f`. Для повторной приёмки исправленных стилей, таймера Spotlight и планшетных сценариев используйте `473dd3cb8fd3f8936cf457189a1c2fff210dbe42`. Проводите проверки с тестовыми мелодиями и отдельным профилем браузера. Записывайте SHA, браузер и версию, устройство или вид эмуляции, язык, размеры, результат и скриншот для каждого сценария.

## Локальный запуск на Mac

```bash
git clone --branch feature/mobile-tablet-ux-tutorial-20261118 https://github.com/reshetnyakr-creator/play12.git play12-browser-qa
cd play12-browser-qa
git switch --detach 473dd3cb8fd3f8936cf457189a1c2fff210dbe42
python3 -m http.server 8770 --bind 127.0.0.1
```

Откройте [браузерный стенд](http://127.0.0.1:8770/MVP/tests/browser/mobile-acceptance.html?scope=matrix). Выполняйте прогоны последовательно. Кнопка **Run fresh acceptance** использует настоящий браузер, но размеры и типы устройств задаются стендом. Сохраните JSON из `#results` после каждого сценария. Держите вкладку теста на переднем плане, особенно в Tutorial и Spotlight. Дождитесь окончания прогона перед любыми изменениями в каталоге предпросмотра. Для независимых сценариев используйте отдельное приватное окно, закрывая все предыдущие приватные окна перед запуском нового, чтобы исключить общие IndexedDB и localStorage.

| Параметр scope | Проверка |
| --- | --- |
| matrix | Main RU/EN, ориентации, переполнение, компоновка, видимые раунды |
| clipboard | Вставка MusicXML на обоих языках |
| workspace | Библиотека, Backup, редактор, Grab |
| files | Файловый импорт через File/DataTransfer |
| persist | Настройки при смене языка, ориентации и перезагрузке |
| security | Отказ Clipboard API, ограничение размера, отображение текста |
| spotlights | Геометрия подсветки и подсказки на нескольких размерах |
| course | Все шесть этапов с обычным состоянием. Добавьте `&width=390&lang=ru` или замените ширину на `768` (планшет портрет), `1024` (планшет горизонтально), `1366` (Desktop) и язык на `en`. После запуска нажмите Play в приложении, когда стенд покажет **Native Play required**, и повторно при **Native Practice Play required**. |
| midi | Проверка с эмуляцией MIDI |

## Ручная проверка

- Откройте главную, Manual, Manifesto, Main, Tutorial и Import на RU/EN и проверьте старые ссылки Editor/Onboarding. Проверьте рабочие CTA, строки шапки, компактные CTA планшета и отсутствие прокрутки страницы по горизонтали.
- Пройдите 375×667, 390×844, 430×932, 844×390, 768×1024, 820×1180, 1024×768, 1180×820, 1366×768, 1920×1080. Для Main запишите число полностью видимых раундов и проверьте совпадение краёв панелей. Проверьте блокировку только Main/Tutorial в альбомной ориентации телефона и три колонки планшета.
- Проверьте переход между панелями жестом, стрелкой и вкладкой, последовательность Grab, руки, BPM, Practice, Loop, From/To, Pre-count и ноль. Импортируйте одну и несколько тестовых мелодий, проверьте доступ к последней записи, Edit, Undo/Redo, Delete/Cancel и выгрузку/восстановление Backup через интерфейс.
- Пройдите все шесть этапов Tutorial на каждом языке на телефоне, планшете и Desktop. Снимайте Spotlight на Play, Pause, карточках, выборе нуля, клавишах, Practice, BPM, Grab, Loop и Pre-count. Проверьте отсутствие перекрытий, доступность активного этапа, анимацию первого перехода, reduced motion, поворот и диалог Confirm your 0, включая выбор другого нуля.
- Импортируйте реальные `.xml`, `.musicxml` и `.mxl` через системный диалог. Вставьте валидный и невалидный MusicXML вручную и проверьте отказ Clipboard API. Подтвердите открытие композиции в Main и доступность редактора. Проверьте сохранение композиции, позиции, этапа, языка и настроек после перезагрузки и поворота.
- На iPhone/iPad Safari повторите проверку Spotlight, свайпов, вставки и загрузки файлов с открытой и скрытой панелью браузера. Для физического MIDI подключите клавиатуру, проверьте калибровку, отключение и повторное подключение. Зафиксируйте эти результаты отдельно от эмуляции.
