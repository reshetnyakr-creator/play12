# Почему пунктирные ноты закрывают центральную колонку

Converter, Engine и Result сохраняют идентификатор, время, длительность, высоту и руку. При пустом пальце и включённом unassignedDisplay resolver выбирает режим unassigned. renderPlay12 задаёт x левого блока как handWidth, правого как rightStart − blockWidth. Оба значения внутри счёта [100; 132] при проверенной ширине клетки 20. Ширина пунктирного блока 10⅔. Левая рука всегда получает x=100, правая x=121⅓. y зависит от музыкального времени и длительности. При одинаковом x блоки одной руки с пересечением по времени накладываются.

| Наблюдение | Time | No Surprises |
| --- | ---: | ---: |
| Уникальные неназначенные SVG-блоки | 72 | 103 |
| Из них в колонке счёта | 72 | 103 |
| В другой графической колонке | 0 | 0 |
| Продолжения лиг без отдельного блока | 0 | 17 |
| Пары неназначенных контактов одной руки с пересечением по времени | 64 | 74 |

В реестре x/y — координаты SVG. renderer_contact_representative указывает первый сегмент цепочки. Указаны поля SVG ID, рука, палец, MIDI и пунктир. Формула работает также до Stage 2.4.2.

Resolver трактует null, undefined, отсутствующее поле и null с диагностическим статусом как unassigned. Целые 0 и 6 он классифицирует как selected. В реальных импортах 0 и 6 не встретились.

На каждой из 192 нот протестированы все пять ручных вариантов через edit, хотя бы один доступен для каждой ноты. Девять представителей проверены через интерфейс, включая обе руки, октавный случай и лигу. Ручное назначение меняет x на колонку пальца. Undo возвращает пунктир, Redo повторяет изменение. Сохранение и повторное открытие подтверждены на каждой композиции. Ручная правка может принимать назначения с предупреждением о предполагаемом удержании, повторе MIDI или превышении порога. Такой ввод не доказывает, что конфликт разрешён по правилам автоматического назначения.
