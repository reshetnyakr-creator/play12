`experiment.cjs` принимает исходную модель, исходный контактный план, профиль начинающего, ручные назначения и, при наличии, проверенные минимальные интервалы возврата по MIDI в четвертях для конкретного случая. Выход содержит физические интервалы, отдельные статусы измерений, сопоставление исходных ID общим контактам, пальцы, конфликты и состояние ограниченного поиска. Проверка диапазонов использует действующий профиль. Неприемлемые варианты отмечаются `rejected`. Путь для каждого межручного унисона сравнивается по полноте назначения, MaxComf, величине превышения MaxComf и существующей суммарной стоимости. Для H1 дополнительные назначения восстанавливаются штатным методом при фиксированной карте Stage 3.0.4.

## Воспроизведение

1. Поднять HTTP-сервер из корня checkout, например `python -m http.server 8735`. Подать оба оригинальных MXL в локальный Play12 через `MVP/docs/stage-3-0-2-partial-fingering-recovery/browser-import.cjs`. Скрипт принимает адрес сервера, приватную папку выгрузок, число повторов `1` и пути к обоим MXL. Полные выгрузки и скриншоты автора остаются локально.
2. Из каталога отчёта выполнить `python audit.py <выгрузки> <оригиналы> --c-register` и сверить результат с `c-register.json`. Без флага результат сверяется с `cases.json`. `node check-existing.cjs <выгрузки>` воспроизводит `existing-plan-results.json`.
3. Выполнить `node run.cjs <выгрузки>` и сверить с `results.json`. Скрипт накладывает опубликованную разницу строгой карты Stage 3.0.4 на исходную выгрузку, проверяет сохранность модели и исходных событий и пересчитывает G1–G4.
4. Открыть [comparison.html](comparison.html) через локальный сервер, загрузить исходную выгрузку No Surprises и два авторских снимка. Снимок с отдельными восьмыми C4 соответствует такту 51. Снимок с четвертью C4 на третьей доле соответствует такту 53. Выбор строки выделяет фактический блок Play12. Для автоматической проверки выполнить `node check-visual.cjs http://localhost:8735 <выгрузка-No-Surprises> [снимок-51] [снимок-53]`. При необходимости указать `PLAYWRIGHT_MODULE` и `CHROMIUM`.
5. Из корня выполнить `node --test MVP/tests/*.cjs MVP/docs/research/stage-3-0-5-physical-contact-semantics/experiment.test.cjs` и `python -m unittest discover -s MVP/tests -p 'test_*.py'`. В проверенном прогоне прошли 362 JS и 9 Python тестов, включая 11 новых. Отдельно проверены исходные MXL, стабильность результатов и визуальное сопоставление в Chromium.

Возврат клавиши и акустическое удержание на реальном инструменте остаются открытыми. Вопросы G3/G4 не меняют действующую модель. Исследовательские материалы не подключены к рабочему движку или маршрутам приложения.
