# Модель с общей временной координатой

Рекомендуется расширение существующего ядра. Все точки задаются рациональными четвертями. Карта метра добавляет смысл к координатам, диапазон Round ссылается на них, а PlaybackClock является единственным преобразованием длины в секунды. Ферматы и исполнительские сдвиги проходят через отдельное отображение из нотной координаты в исполнительскую. Хранить provenance и версии политики поверх оригинала.

```ts
type Q = string // сокращённое p/q
type Meter = {
  at: Q, parts: {numerators: number[], denominator: number}[],
  free: boolean, scope: {partId: string, staff?: number}
}
type Bar = {id: string, from: Q, to: Q, nominal: Q | null, metricPhase: Q}
type Round = {id: string, from: Q, to: Q, barIds: string[]}
type Count = {at: Q, length: Q, accent: 'primary'|'secondary'|'weak', subdivisions: Q[]}
type Grouping = {counts: Count[], provenance: string, confidence: 'explicit'|'conventional'|'inferred'|'unknown'}
type TempoMark = {at: Q, unitQ?: Q, perMinute?: string, soundQpm?: number, source: string}
```

1. Распарсить последовательность XML в нотное время. Для нескольких партий согласовать границы по общей карте, при конфликте показать предупреждение и использовать явную основную партию для учебного счёта.
2. Построить фактические интервалы тактов. Присоединить фазу затакта при известном полном размере, отделить время такта от фазы. Для спорной длительности короткого такта опубликовать диагностическое решение, сохранив исходные события.
3. Вывести Count из последовательности групп `g[i]`. Длина = `4*g[i]/D`, начало = сумма предыдущих длин + начало метрического цикла. Пересечь с диапазоном такта, сохранив индекс и оставшиеся подразделения. Для составных знаменателей считать длину каждой группы с её D. Для 12/8 рациональные позиции 0, 3/2, 3, 9/2. Для 2+3/8 позиции 0, 1, а для 3+2/8 — 0, 3/2. Для 2+3+2/8 — 0, 1, 5/2.
4. Сконструировать интервалы Round. На первом этапе принять один такт на раунд для импорта, сохранив возможность нескольких ссылок на такты. При переходе ноты через раунд хранить единственный контакт и рисовать сегменты по окну просмотра. Не менять IDs нот из-за смены счёта.
5. Нормализовать `QPM = printedBPM * unitQ` при отсутствии воспроизводимого sound tempo. Одновременные конфликтующие метки сохранять, применить sound с диагностикой. Для этого слоя использовать позиции после исполнительской трансформации там, где она нужна. Разность времени: сумма `deltaQ*60/effectiveQPM` по сегментам.
6. При обычном воспроизведении брать Count для акцентных звуков и мигания из одного списка событий. При Practice waiting заморозить продвижение нотного времени и повторять локальный шаблон групп в звуковом времени, пока пользователь не продолжит. Окна атак сдвигаются вместе с общей фазой. Режим рук фильтрует ожидаемые контакты, сохраняя метр. Loop использует исходную фазу на входе и выходе, при повторе сбрасывает только anchor; при Pre-count строит виртуальный локальный цикл. При 12/8 один цикл — 4 удара, два — 8. Опциональный режим подразделений — 12/24 соответственно. Для свободного метра доступен включаемый равномерный вспомогательный пульс.
7. Renderer выводит пропорциональные времени зоны счёта, сохраняет цвет карточек и слабую разметку подразделений. Атаки между линиями, включая триоли, используют прежнюю точную координату. Обозначения и вид счётного слоя согласуются по прототипу.

## Пользовательское изменение темпа

В Stage 2.3 исходная единица поля технически QPM. Предложение для совместимости — сохранить абсолютную разность в QPM и диапазон пользовательского ввода 20–300 QPM. При исходных 94,5 и пользовательских 105,5 разница +11 QPM применяется к каждому авторскому QPM, с нижней границей 20. Десятичный ввод в примере служит формулой, действующий интерфейс принимает целые числа. Original сохраняет печатный темп и его единицу, а в UI можно отобразить эквивалент: при четверти с точкой 20–300 QPM означает 13⅓–200 в минуту, при половинной 10–150, при восьмой 40–600. Когда единица меняется, фиксированный QPM-offset даёт разные приращения в печатных BPM. Альтернатива — фиксированная разность по единице, выбранной для UI один раз на весь документ. Тогда преобразование `deltaQPM = deltaDisplay * documentUnitQ` сохраняет абсолютность. Динамически менять шкалу пользовательской поправки вслед за маркировкой рискованно: при эквивалентной модуляции получится скачок. При смене сегмента починить шкалу можно только с решением автора о единице и диапазоне.

При паузе, seek, рестарте и изменении темпа менять привязку Clock и пересчитывать очередь будущих щелчков. Для расхождений после длинных сессий проверять обратное преобразование и реальные timestamps планировщика. В Fingering Engine передавать те же onset/release/tempo, а смену только метрической группировки проверять равенством контактных профилей. Исправление потерь темпа выносить отдельно с пересчётом подтверждённых случаев.
