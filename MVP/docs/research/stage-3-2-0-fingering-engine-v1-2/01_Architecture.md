# Архитектура исследовательского ядра v1.2

Код запускается через Node.js без изменения редактора. Входы: snapshot(score,{manual,profile,resetByMidi}) для подготовленного MusicXML-импорта либо явная модель события и контактного плана. run(input, options) возвращает отдельные карты исходных событий, физических контактов, удержаний, позиций, фразовых и мотивных кандидатов, рук и пальцев, ручных locks и независимых статусов назначения, движения и звучания. why(eventId) выполняет по запросу альтернативный поиск с фиксированным рассматриваемым пальцем, без записи его как ручного. Поиск воспроизводим для одинакового подготовленного входа и бюджета.

| Слой | Реализовано | Граница |
| --- | --- | --- |
| L0 | Пальцы и владение контактом, интервалы полуоткрыты, защита ручных пальцев, запрет E08/R35, MaxPrac и направленная октава. Контакты с неустранённой коллизией клавиши отбрасываются. | Геометрия позиции одномерная и приближённая. Не подтверждает биомеханику. |
| L1 | Атаки и удержания, тай и подтверждённая реализация из импортёра, повторное использование контактного планирования и специальных форм прошлых этапов, голоса, интервальные кандидаты мотивов и паузные кандидаты фраз. | Формальные музыкальные границы и гармонический анализ не установлены. |
| L2 | Полный поиск по моделируемой руке, совместный проход разных пальцев и естественного порядка на узком шаге, далее соседние пальцы, чёрные и остаточные показатели позиции. | Граница зависимой группы и доказательство сохранения общей области сведены к контактам и узким переходам. Полный педагогический приоритет v1.2 этим не заменён. |
| L3 | Повтор на той же клавише не считается переходом R22. Два ручных конца сохраняются. E07 выдаётся только после отдельного конечного поиска без конкретного повторного ребра; при альтернативе или исчерпании бюджета путь блокируется. Нотированные специальная форма и освобождения из прежнего эксперимента идут отдельным входным планом. | feasibility.cjs отдельно перебирает точную дискретную модель для E07 и одновременную форму E05 без весов. |
| L4 | Стоимость — последняя компонента сравнения, после дискретных критериев; нормализация нечисловых весов и детерминированный обход. | Не все педагогические факторы реализованы как обязательные фильтры. |

Состояние динамического поиска содержит назначения текущего слоя и продолжающихся контактов. Остаточные связи используют текущую форму и известную информацию о соседних слоях. Сохраняются разные состояния для разных удерживаемых пальцев. Объединение состояний с одинаковой картой корректно только для фактически моделируемых факторов. Поза руки в реальном пространстве, связанная история, темп и акустический результат потребуют расширения состояния.

verify.cjs независимо от поиска проверяет раздельную проекцию, ручные locks, диапазон пальцев, покрытие картами контактов, запрет PRO, занятость, диапазон и формы по действующему валидатору. Проверяет внутренние пары отдельных позиций и формат сертификатов. Отдельно тестируются повреждённый результат и выход за физические пределы. Статус ok означает отсутствие найденного структурного нарушения, а не полноту покрытия или подтверждение физической выполнимости.
