# Fingering Engine v1.2 · проект спецификации

Статус — предложение Stage 3.1.0 для профиля «Начинающий». Нормативная поставка возможна после решений [D01–D08](16_Author_Decision_Register.md).

1. Вход имеет неизменяемые музыкальные события с рукой, голосом и нотным временем, отдельный профиль инструмента, кисти и ручных назначений. Производный контакт связывает один или несколько исходных ID с физической клавишей и интервалом. Результат хранит раздельные статусы назначения, движения и звучания.
2. Валидация L0 проверяет R01/R02/R03/R04/R06/R07/R08/R09/R30/R31/R39/R42/R43/R45, а также требования ручной транзакции и неопределённости. Нарушение нельзя компенсировать назначением дополнительных пальцев.
3. L1 определяет множество допустимых контекстов по реестру. Внутри каждой реальной позиции применяется общий предикат занятости и все ограничения пар. Для специального широкого аккорда согласованные пальцы и позиции хранятся отдельно от нотной одновременности.
4. L2 задаёт приоритеты согласно [иерархии](06_Proposed_Rule_Hierarchy.md). Сохранение комфортной позиции при естественном порядке требует проверяемого продолжения через зависимую группу. Компоненты приоритета не суммируются с L4. При спорном пересечении с R22 применяется D01.
5. L3 задаёт только область явно разрешённого уточнения по [реестру](09_Exception_Register.md). Отсутствие прогресса эвристики не даёт права ослабить правило. Исключения отслеживаются по событию и версии.
6. L4 сравнивает прошедшие пути. Коэффициенты калибруются отдельно. При равенстве используется стабильная последовательность ID без утверждения о физиологическом превосходстве.
7. Движок возвращает выдачу причины по каждому назначению и явный статус исчерпания. Приёмка требует независимой проверки контактов, A01–A16 и полного корпуса регрессий. Предложение не вводит численные пороги человеческих движений.

Нормативные приложения проекта — [реестр R01–R60](04_R01_R60_Rule_Audit.md), [формальная модель](07_Formal_Hand_Position_Model.md), [решающий алгоритм](10_Proposed_Decision_Algorithm.md), [контракты](12_Proposed_Test_Contracts.md) и [метрики](14_Quality_Evaluation_Framework.md).
